# Criteria

Within [quality](README.md), documentation quality is one judgement over every applicable requirement. Meaning, structure, style, and local documentation own the requirements. Evidence determines whether the complete result meets them.

## Use the pillar standards

Use [meaning](../meaning/README.md) for what the documentation says and what readers may rely on. Use [structure](../structure/README.md) for how documentation is arranged and connected. Use [style](../style/README.md) for how documented meaning is expressed.

Each pillar owns its requirements and defines where they apply. Each pillar's README leads to the detailed standards.

Local documentation can add narrower requirements for its own surface. Those requirements apply alongside the pillar standards.

## Require the whole result

Judge each document and its local documentation surface. A clear leaf fails when readers cannot find it or its index misrepresents it. A coherent surface fails when a necessary claim is false or a necessary instruction is unreadable.

Every applicable requirement must be satisfied. Correct meaning cannot compensate for unusable structure or style. Clear presentation cannot compensate for false meaning.

## Require adequate evidence

Evidence must address the requirement and the conditions it judges. A lint result supports only the rules the linter checks. A test result supports only its assertions under its recorded conditions. A review supports only its recorded subject and quality coverage.

The documentation passes when adequate evidence establishes every applicable requirement. It fails when the evidence establishes that any requirement is violated. The result is inconclusive when material evidence is missing, contradictory, or too weak to decide.
