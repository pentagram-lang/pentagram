# Tests

## Find and apply the documentation standards

**Task**

A contributor needs to document new public behaviour for a parser subsystem. Where should the governing documentation live, how should the contributor navigate to Pentagram's shared documentation standards, and what relationship should the documentation have to implementation and tests? Explain how you found the answer.

**Assert**

- The answer places governing documentation beside the parser subsystem rather than treating `doc/` as a subject warehouse.
- The answer makes the parser subsystem's `README.md` the local entry point and links shared guidance from that entry point.
- The answer identifies documentation as the primary semantic authority and requires implementation and tests to realize or validate the documented meaning.
- The answer requires correct, high-quality documentation rather than treating any prose as sufficient authority.
- The answer connects local placement to the owning system and the smallest complete scope.
- The answer cites the documentation standards root and topology document and explains how they govern the result.
